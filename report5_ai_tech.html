Ⅰ. 문서의 성격

이 문서는 Phase 4 산출물을 대체하지 않습니다. Phase 4의 사례 데이터(261건)와 NCS 공식 골격은 그대로 두고, 기술의 공통/특화 분류 방식만 다시 계산합니다. 사례·근거·URL·usage_desc 원본 문장은 손대지 않았습니다. 산출물은 outputs/data/ncs_ai_map_v3.json(신규)에만 저장되며 Phase 4의 ncs_ai_map.json은 그대로 보존됩니다.

Phase 4와의 관계

Phase 4는 NCS 24개 대분류 각각에 "AI 공통기술" 노드를, 81개 중분류 각각에 "AI 특화기술" 노드를 만들었습니다. 이때 기술이 공통인지 특화인지, 특화라면 어느 중분류 소속인지는 데이터를 사례에 배치하기 전에 사람이 미리 정한 값이었습니다. Phase 5는 그 소속을 사람이 미리 정하지 않고 사례가 실제로 인용한 (대분류, 중분류)만으로 매번 다시 계산합니다.

Ⅱ. 문제 진단 — Phase 4 고정 분류의 한계

Phase 4 빌드 스크립트(build_ai_ext.py)는 특화기술마다 소속 중분류를 기술 마스터에 고정값으로 미리 넣어 두고, 그 기술을 인용한 사례를 전부 그 고정 소속 하나로만 집계했습니다. 그 결과 사례가 실제로는 서로 다른 중분류에서 같은 기술을 인용해도 검증 단계에서는 항상 "특화기술 단일 중분류 배치 PASS"로 나왔습니다 — 이 검증이 구조적으로 항상 참이 되도록 설계돼 있었기 때문입니다.

Ⅲ. 재분류 방법론

case_tech_map_v2.json 사례 261건이 실제로 인용한 (대분류, 중분류) 조합만으로 기술마다 소속을 다시 계산합니다. 기술 마스터의 기존 소속 고정값은 참고용(prior_type) 으로만 남기고 분류 판정에는 쓰지 않습니다.

  • 공통기술: 서로 다른 (대분류,중분류) 쌍 2개 이상에서 인용됨 → 등장하는 모든 대분류에 AI-C-{대분류} 배치를 만든다.
  • 특화기술: 정확히 1개 (대분류,중분류)에서만 인용됨 → AI-D-{대분류}-{중분류} 배치 1건만 만든다.

이 두 조건은 서로 배타적이므로 공통·특화 사이에 구조적으로 오버랩이 0입니다. 빌드 스크립트(tools/phase5/build_ai_tech_v3.py)가 매 실행마다 이를 자체 검증합니다 — "공통/특화 동시 배치"와 "특화기술의 다중 소속"이 하나라도 나오면 스크립트가 실패하도록 만들었습니다. 이 규칙은 Phase 4 규칙 4.2("대분류 안에서 서로 다른 중분류 2개 이상이면 공통기술로 판정")를 특화기술에도 동일하게 적용해 전체 기술로 일반화한 것입니다.

Ⅴ. 시각화 UI

새 페이지 ai_tech_map_v5.html은 Phase 4 ncs_ai_tree.html의 계층 트리(대→중→소 접이식 + 우측 상세 패널) 디자인을 계승하면서, 두 가지를 더했습니다.

1. 계층 트리 뷰

대분류 24개 → AI 공통기술/중분류 → AI 특화기술 순의 접이식 트리는 그대로 유지하되, 이번에 승격된 기술 카드에는 Phase5 승격(구 특화) 배지를 달아 재분류 이력을 투명하게 보여줍니다.

2. 공통기술 매트릭스 뷰 (신규)

트리만으로는 "이 기술이 몇 개 대분류에서 함께 쓰이는지"를 한눈에 보기 어렵습니다. 매트릭스 뷰는 공통기술 53종(행) × 대분류 24개(열)의 히트맵으로, 칸이 채워진 곳이 그 대분류에서 실제 근거로 확인된 배치입니다. 색 진하기는 중요도, 점선 테두리는 근거수준 '추정'을 나타냅니다. 상하위(교차 분야) 관계를 즉시 시각화하기 위한 것입니다.

3. 상세 패널 공통화

트리·매트릭스 어느 쪽에서 기술을 클릭해도 같은 상세 패널이 뜹니다: 정의, 범주, "이 기술이 쓰이는 대분류 N개" 칩(클릭 시 트리 뷰로 이동해 그 대분류를 자동으로 펼침), 대분류·중분류별 활용 설명과 근거 사례 링크.

Ⅵ. 검증

  • 재분류 자체 검증(build_ai_tech_v3.py): 공통/특화 동시 배치 0건, 특화 다중소속 0건, 사례에서 전혀 인용되지 않은 기술 0건.
  • 시각화 동작 검증: Playwright 브라우저 브리지가 설치돼 있지 않아(Phase 4와 동일한 제약) 실브라우저 렌더링은 확인하지 못했습니다. 대신 로컬 HTTP 서버 + Node/jsdom으로 실제 데이터를 로드해 페이지 스크립트를 그대로 실행했습니다: 트리 전체 펼치기 + 461개 행 전수 클릭, 매트릭스 탭 전환 + 셀 50개·행 헤더 5개 클릭, 기술 150종 전수 상세패널 렌더링, 교차분야 칩 클릭 내비게이션까지 실행해 콘솔 예외 0건을 확인했습니다.

Ⅶ. 한계와 후속 과제

  • case_tech_map_v2.json의 사례별 common_techs/domain_techs 배열은 Phase 4 당시 구분을 그대로 담고 있어 v3의 새 분류와 더 이상 일치하지 않습니다. Phase 5는 이 배열을 "그 사례가 쓴 기술 전체 목록"으로만 사용하고, 공통/특화 판정은 항상 ncs_ai_map_v3.json의 type 필드를 기준으로 합니다.
  • 승격 기준(중분류 2개 이상)은 최소 근거 사례 2건을 자동으로 요구하지만, 일부 승격 기술은 근거 사례가 2~3건으로 적습니다(부록 표의 "근거 사례" 열 참고). 근거 보강이 필요한 항목입니다.
  • 이 재분류(v3)를 Phase 4 산출물에 병합할지 별도로 유지할지는 아직 결정하지 않았습니다. 현재는 사용자 지시대로 완전히 분리된 신규 파일로 유지합니다.
